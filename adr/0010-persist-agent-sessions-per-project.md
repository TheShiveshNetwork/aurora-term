# ADR 0010: Persist agent chat sessions in the app SQLite, scoped per project

- Status: accepted
- Date: 2026-10-02

## Context

Agent view chats had no durable storage. `useAgentStore.sessions` was an
in-memory `Record` that `usePersistUIState` never subscribed to, so every chat
vanished on reload. The Mastra `thread` that carries LLM context lived in
`InMemoryStore`, so a sidecar restart dropped it too. The `sessions` table that
already existed in `crates/aurora-db/src/db.rs` had a nullable `name` column and
zero readers or writers.

Sessions were also named `Session-4821`, generated by `Math.random()` in
`useAgentStore.startTask`. Mastra's `updateThread({ title })` existed but was
never called, and there was no title-generation code anywhere.

Both VS Code and Antigravity store chat history locally per workspace
(`workspaceStorage/<hash>/chatSessions/*.jsonl` plus an index in `state.vscdb`;
`~/.gemini/antigravity{,-ide}/conversations/<uuid>.db` plus
`chat.ChatSessionStore.index`). Both are documented to scope histories to the
workspace they were created in. Both have shipped widely-reported bugs where the
index was lost or reset while the underlying data files survived, making history
invisible until the index was hand-rebuilt.

## Decision

Store agent view sessions in the existing `history.db` via `aurora-db`, scoped by
a project id derived from the canonicalized project path. The Mastra thread
becomes a derived, on-disk *cache* of LLM context rather than the source of truth.

- `agent_projects`, `agent_sessions`, `agent_messages` in
  `crates/aurora-db/src/agent_sessions.rs`. Session rows and the transcript live
  in one database, in one transaction. The session list is derived from those rows
  directly, so there is no separate index to desync from the data.
- `chatHistory` is stored in `agent_messages`, not in the `state` blob, so the
  transcript is never written twice.
- The sidecar's `DurableInMemoryStore` mirrors the `memory` domain to
  `~/.aurora-agent/threads/<threadId>.json` (capped at 400 messages, 45-day TTL).
  Losing a file costs recall continuity for that one session and nothing else.
- Titles are written by the agent. A session starts life with a random
  `session_NNNN` placeholder, which the UI renders in place (shimmered while the
  request is in flight) until the agent returns a 3–6 word name. Title precedence
  (`manual` > `model` > `placeholder`) is enforced in Rust on write, so a late
  model response cannot overwrite a rename the user just made. The generation call
  runs on the zero-tool chat agent with memory disabled and a hard timeout, so it
  can never interfere with an in-flight step; on failure the placeholder simply
  stays.
- Retention: WAL + `auto_vacuum=INCREMENTAL`, per-project scoping, LRU eviction
  of unpinned/unarchived sessions past a total byte budget and a minimum age, and
  oldest-message body trimming for oversized sessions. Pinned and archived
  sessions are never evicted.

Terminal agent tabs are deliberately excluded and stay ephemeral.

The agent view also holds no session until one is needed: opening the app or
clicking "New Session" leaves `activeAgentSessionId` null and renders the hero
view, and the first message sent materializes the session. Sessions are therefore
never created speculatively, so history contains only real conversations. The
sidebar groups sessions by calendar recency (Today, Yesterday, Last Week, Last
Month, Last Year, Over a Year), newest first, from `startedAt`/`updatedAt` which
are stamped at session creation rather than first message.

## Consequences

- Chat history survives app and sidecar restarts and is listed per project.
- Session names come from the agent; until it answers the row shows a random
  `session_NNNN`, and a manual rename always wins.
- Losing the thread mirror degrades gracefully instead of losing history.
- `projectDir` is still a single global path, so "per project" means "scoped to
  whatever project was active when the session was created" rather than a real
  multi-project switcher.
- A model chosen on the hero view before any session exists is held in component
  state and applied to the session created on send.
- The retention budget is a code default, not a user-facing setting, so users
  cannot yet see or tune how much history costs.
- `agent_session_prune` runs on project open, not on a timer, so an app left open
  for weeks will not trim until the project is reopened.
